## Decisions made

- Removed `Header`/`Footer` from the root layout entirely rather than keeping a "default" instance there. There's currently no page that renders body content directly under the root — everything real lives under a year's own layout, or is a redirect that never renders a body — so a root-level instance would have been dead code.
- `Header`/`Footer` take an optional `year` prop (default `CURRENT_EDITION.year`) instead of sniffing `usePathname()`. Removed `getEditionFromPath` from `editions.ts` since nothing needs it anymore.
- Kept `Header`/`Footer` as one shared, parameterized component rather than literally forking them per year — there's nothing yet for a year's nav to diverge in shape from. Refork only when a year's nav structure actually needs to differ, consistent with how page content is already handled.
- `/about-cyclethon` and `/about` nav hrefs point at their current real location (`/2026/about-cyclethon`, `/2026/about`) rather than a hypothetical future unprefixed one — operator mentioned these will likely become year-agnostic pages later, but that hasn't happened yet, so linking to where the content isn't yet would just add a redirect hop today for no benefit.

## What I worked on

Operator asked for a full audit before moving on, to make sure the year-scoped routing work was actually complete rather than assuming it from the fixes so far. Found and fixed three real bugs, then committed the whole arc.

## Decisions made

- No scope decisions this pass — this was verification and bug-fixing against decisions already made, not new architecture.

## What I learned

- **Found a self-redirect loop:** `/2026/stats/donation-war/page.tsx` was still `export { default } from '@/app/stats/donation-war/page'` from the original Phase 2 pass. Once the unprefixed page became a redirect (during the full-encapsulation rework), this re-export started redirecting to itself — the real donation-war page was unreachable at any URL, and neither `npm run build` nor `npm run check` caught it, since a redirect-to-self is valid TypeScript and valid Next.js, just wrong behavior. Recovered the original component from `git show HEAD:src/app/stats/donation-war/page.tsx` (still in history since nothing had been committed yet) and moved it to live directly under `/2026/stats/donation-war/page.tsx`.
- Three page titles (`journey`, `donations/search`, `donations/top`) still said `| 2026 Archive`, left over from the superseded first pass. Cosmetic, but actively misleading since these pages show live current data.
- `JourneyProgress.tsx` had the same hardcoded `/journey/${slug}` pattern as `DayNav`, missed in the earlier sweep because it's a template literal, not a plain string — the grep pattern that caught the others only matched literal `href="/..."` strings. It's not currently imported anywhere, so not user-visible, but now correct.
- Also renamed 7 leftover `Archived*Page2026` function names (journey, donations/search, donations/top, ja, en, day, donations-redirect) — cosmetic, not user-facing, but confusing to read given these pages are not archived.
- Confirmed via curl that a redirect-loop bug like the donation-war one won't be silently missed again: status-code sweep across every route (12 unprefixed → 307, 12 `/2026/...` → 200, `/jp` → 404) is now the standard verification pass for this kind of change, not just `npm run build`.

## Problems / friction

Grep-based verification of rendered content on a page wrapped in `<Suspense>` with client-side `useSearchParams()` was unreliable — text can be split across RSC streaming chunks in ways that defeat simple substring search. Fell back to status code, payload size, and the router's serialized flight state (which explicitly showed `type=anime` was parsed correctly) as more reliable signals than trying to grep for exact rendered text.
