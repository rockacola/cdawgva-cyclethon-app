# 2026-09-12

## What I worked on

Ran `npm audit` and resolved all 15 flagged vulnerabilities (13 via `npm audit fix`, the last 2 via a forced Next.js 15 → 16.3.5 major bump, at the operator's direction). Also added `.ai/standards/writing-style.md`, adapted from the equivalent standard in `travislin.com_v5` for this project's product-copy context.

## Decisions made

- **Forced Next.js 16 upgrade accepted.** The remaining postcss vulnerability only resolved through a major Next bump; operator chose to attempt it rather than leave it.
- **`next lint` migrated to plain `eslint`.** Next 16 removed the `next lint` subcommand. Ran the official `@next/codemod next-lint-to-eslint-cli`, then scoped `lint`/`lint:fix` to `eslint src` (rather than the codemod's default `eslint .`) to preserve the same file coverage `next lint` had (pages/app/components/lib/src), avoiding scope creep into `scripts/` and `cypress/`.
- **Restored `@eslint/eslintrc` devDependency.** The codemod dropped it from `package.json` even though `eslint.config.mjs` still imports `FlatCompat` from it for the `prettier` config extension — would have broken a clean install.
- **Bumped `eslint-config-next` to 16.3.5** to match the new `next` version.
- **Fixed 4 newly-surfaced `react-hooks` lint errors** (purity, set-state-in-effect, use-memo) that the upgraded `eslint-config-next` now catches. Used the existing `useNow()` hook in place of raw `Date.now()` calls in the two donation feed components, and the render-time "adjust state when a prop changes" pattern in `Header.tsx` instead of an effect.
- **Writing style guide adapted, not copied.** Source guide is written for a first-person personal blog (Travis speaking directly, MDX notes). This app has no first-person narrator and no blog, so voice/tone was rewritten for product/donation-tracker copy; the Notes/Blog section was dropped entirely. Language rules (no em dashes, numerals, Australian/UK English, banned-patterns list) carried over largely as-is — UK spelling already matches existing usage in `docs/` ("colour mode").

## What I learned

- Next.js 16 auto-rewrites `tsconfig.json` on build/typecheck (`jsx: preserve` → `jsx: react-jsx`, adds `.next/dev/types/**/*.ts` to `include`). Expected, not a bug; just needed reformatting to match Prettier style.
- A scan of `src/messages/en.json` against the new writing-style standard turns up a couple of banned-pattern hits worth a future cleanup pass ("incredible community coming together", "empower families") — not fixed in this session since it's a separate content-editing task from tooling/security work.

## Problems / friction

`npm audit fix --force` and its codemod each made assumptions (widened lint scope, dropped a still-needed dependency) that needed manual correction rather than trusting the automated output as final.

## Next step

Do a first copy-editing pass over `src/messages/en.json` and page copy against `.ai/standards/writing-style.md`, starting with the flagged "incredible"/"empower" lines.

## What I worked on

Implemented Phase 2 of `.ai/tasks/active/year-scoped-editions.md`: forked 2026's homepage/journey/donations/stats routes into `src/app/2026/...`, added the `/`, `/ja`, `/en` redirects to the current live edition's year-scoped path, and made Header/Footer hide the Donate CTA on archived routes.

## Decisions made

- Reused presentational leaf components (`JourneyPageContent`, `TopDonors`, `DonationSearcher`, the donation-war table) as-is inside the `/2026` fork rather than duplicating them. They have no live/frozen assumption baked in — only route/layout files and data-fetching were forked. Full duplication of every dependency was considered and rejected as disproportionate; flagged to the operator so they can push back if stricter isolation was intended.
- Dropped `/2026/donations/live` entirely rather than building a "static replay" — a live feed has no meaning for a concluded campaign (operator's call).
- Made `DonationsProvider` take an optional `sourceUrl` prop (default: the existing live URL) instead of duplicating it for the archive. This was a necessary infrastructure fix, not just a convenience: without it, `TopDonors`/`DonationSearcher`/the donation-war page's `useDonationsPolling` would have silently overwritten an archived page's frozen data with a poll against the _live_ current-year feed a few minutes after page load.
- Archived fetchers (`src/app/2026/_lib/`) fall back to an empty shape on a failed fetch instead of throwing.

## What I learned

- `next build` prerenders `/2026/...` at build time by default, and the `2026/` R2 path doesn't exist yet (Phase 3 hasn't run) — the first build attempt crashed the entire production build, not just the archive pages, because the archived fetchers let a 404 propagate as a thrown error. Fixed by having them catch and fall back instead. Important because `/` now redirects to `/2026`, so this would have taken down the homepage for every visitor, not just archive-browsers.
- Caught a related bug during manual verification: `Header`/`Footer`'s "hide Donate CTA on archived routes" check was keyed on the registry's `isLive` flag, but 2026 is still marked live until Phase 3 flips it — so the CTA wasn't actually hiding on `/2026` despite the page showing a "concluded" banner. Fixed by keying the check on "is this path year-prefixed at all" instead, which is unambiguous by construction (the live edition is never served from a year-prefixed path).

## Problems / friction

The build-crash and CTA bugs above were both only caught by actually running `npm run build` and curling the running dev server — typecheck and lint were clean in both cases. Confirms this class of change needs a real build/runtime check, not just static analysis.

## Next step

Start Phase 3: decide the freeze trigger and run the one-time R2 copy for 2026.

## What I worked on

Operator caught that Phase 2's first pass was inconsistent: `/donations/*` (and `/about`, `/about-cyclethon`, `/finish-line`) weren't migrated under `/2026/*`. Reworked Phase 2 to fully encapsulate every route under `/2026/...`, with all the old unprefixed routes becoming thin redirects.

## Decisions made

- **Corrected a design mistake, not just a scope gap.** The first pass had `/2026/...` unconditionally fetching from a frozen R2 path that doesn't exist until Phase 3, which is why `/2026/donations/live` had been dropped ("a live feed means nothing for a concluded campaign") — but 2026 isn't concluded. Fixed by having `/2026/...` use the same live data-fetching (`getDonations`, `getDonationsFull`, `getStats`, `getCampaignFact`) as the old unprefixed pages, while `isLive` stays true. Deleted the now-pointless `src/app/2026/_lib/` frozen-fetcher module from the first pass.
- Moved `/about`, `/about-cyclethon`, `/finish-line`, and `/donations/live` under `/2026/...` and turned their old locations into redirects, matching the pattern already used for `/`. Deleted the now-unneeded `journey/layout.tsx`, `donations/layout.tsx`, `stats/layout.tsx` at the unprefixed level, since those routes never render content directly anymore.
- `/stats/donation-war`'s redirect forwards its query string (`?type=`, `?start=`, `?end=`) — it's a client component that reads `useSearchParams()` for filtering, so a plain redirect without the query would have silently dropped the filter.
- Reverted the Header/Footer "hide Donate CTA" check back to `pathEdition && !pathEdition.isLive` (from "any year-prefixed path") — now that `/2026/...` is genuinely the live experience while `isLive` is true, hiding the CTA there would be wrong; it should only hide once an edition is actually archived.
- Removed the "View the 2026 archive" links (`AboutCyclethonContent`, footer) added in the first pass — they assumed a separate live/archive split that no longer exists (every unprefixed link already redirects to `/2026/...`). Noted to re-add once 2026 is a genuine past edition.

## What I learned

The "fork, don't share" ADR decision was correct, but I'd initially applied it one layer too early — forking the _data source_ (live vs. frozen) at the same time as forking the _route tree_, when only the route tree needs to exist ahead of time. A year's own tree should track its own `isLive` state and only flip to frozen data at that year's actual freeze time.

## Problems / friction

None — the fix was mechanical once the model was corrected; `npm run check` and `npm run build` stayed clean throughout.

## Next step

Start Phase 3 once the Tiltify campaign has actually concluded: decide the freeze trigger, run the one-time R2 copy, and update `/2026/...`'s data-fetching in place to point at the frozen snapshot.
